# v0.7.0 VCPedia 数据获取重构：从 HTML 爬取改为 MediaWiki API + wikitext 解析

## 背景与问题

当前 `server/src/world/get_new_songs/` 通过直接请求 VCPedia 的页面 HTML 获取歌曲数据：

- `vcpedia_fetcher.py`：请求 `https://vcpedia.cn/<页面名>`，用 BeautifulSoup 解析 `moe-infobox`、`h2` 简介段落、歌词 `<poem>` 等 DOM 结构。
- `daily_new_song_fetcher.py`：请求 `https://vcpedia.cn/Template:洛天依/<年份>` 的渲染后 HTML，从链接文本中过滤出歌曲名列表。

依赖渲染后 HTML 存在多个问题：

1. **反爬脆弱**：页面会返回反爬挑战页，代码只能退化为 `curl` 兜底，仍需依赖运行时机器上安装了 curl。
2. **解析脆弱**：HTML 结构是渲染结果，样式、模板展开、`display:none` 过滤都耦合进了解析逻辑；页面结构一变就要重写解析器。
3. **效率低**：为拿到一小段正文要下载整个页面 DOM，网络请求慢且占用带宽。

VCPedia 是 MediaWiki 站点，提供标准 `api.php`。通过 `action=query&prop=revisions` 或 `action=parse&prop=wikitext` 可以直接拿到原始 wikitext，请求小、稳定、不依赖渲染 HTML，是 MediaWiki 生态的标准获取方式。

## 大目标

把「新歌知识同步」数据获取层从「抓取渲染 HTML + BeautifulSoup 解析」重构为「MediaWiki API 获取 wikitext + 解析 wikitext」，同时：

1. 保持 `sync_daily_new_songs` 的对外契约（返回 `{"added": [...], "failed": [...]}`）和 `VCPediaNewSongTask` 行为不变；
2. 解析结果字段保持兼容：`name`、`type`、`infobox`、`summary`、`lyrics`、`spaced_lyrics`、`short_summary`；
3. 逐步删除对 HTML 抓取与 BeautifulSoup 解析的依赖；
4. 更新 config 模板、README 说明与接口 spec 文档。

## 用户使用路径

功能上没有面向终端用户的可见变化。变化在服务端后台「新歌知识同步」任务的数据来源与实现方式：

- 任务仍每天定时运行（`world.song_knowledge.clock_config`）；
- 歌曲条目来源仍按年份模板页（`Template:洛天依/<年份>`）获取，改为读取该模板的 wikitext；
- 每首歌曲的简介、infobox、歌词改为从 MediaWiki API 获取 wikitext 后解析。

## 功能清单

1. 提供 MediaWiki API 客户端：按页面名获取 wikitext。
2. 从「洛天依/年份」模板 wikitext 中解析出歌曲名列表（替代 `fetch_song_list_from_template` 的 HTML 解析）。
3. 从歌曲页面 wikitext 中解析出 infobox、简介摘要、歌词等字段（替代 `VCPediaFetcher._parse_page` 的 HTML 解析）。
4. 删除 HTML 抓取与 BeautifulSoup 解析路径（`requests` 到页面 HTML、`curl` 兜底、`_is_bot_challenge` 等）。
5. 更新接口 spec、config 模板与 README 中的数据来源说明。

## 最终验收标准

1. 配置使用 MediaWiki API 时，新歌同步任务能列出当年歌曲并成功入库，返回 `added`/`failed` 列表。
2. 入库歌曲包含与旧 HTML 路径等价的字段：上传者、演唱者、简介、歌词。
3. 离线测试不访问真实 VCPedia，使用固定的 wikitext 样例验证解析行为。
4. 仓库中不再保留对页面 HTML 抓取（`base_url + /页面名`）与 `curl` 兜底的调用路径；BeautifulSoup 不再用于新歌数据获取。
5. `sync_daily_new_songs` 的调用契约（`VCPediaNewSongTask` 与 `WorldRuntime` 现有用法）不改变。

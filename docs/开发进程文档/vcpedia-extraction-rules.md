# VCPedia 歌曲提取规则与缺口补提

## 用户故事

- 作为角色使用者，我希望天依"学会"的新歌，其信息框、简介与歌词按站点源码的真实结构提取，以便陌生格式的歌曲页也能被正确记录，而不是取到空值或错误版本。
- 作为维护者，我希望模板取文槽与角色名映射放在配置文件里，站点模板改名或换参数时只改配置、不改 Python，以便不需要每次发版。
- 作为运维者，我希望页面确实缺字段时能由模型补一次，并且补提失败不影响原有的摘要，以便新歌知识尽量完整而不会因为一次模型异常整体失败。
- 作为使用者，我希望歌词保留原文换行、括号与和声，以便记下来的歌词与页面一致、可被现有检索消费。

## 验收标准

### 信息框

1. **状态**：页面存在歌曲框；**输入**：首个歌曲框与其相邻创作者名单模板；**输出**：信息框取首个歌曲框的开放业务字段与相邻 staff 的角色字段。首个歌曲框**之前**的 staff 不并入该信息框；后一个歌曲框不覆盖首个框的字段。
2. **状态**：歌曲框参数中混有展示控制项；**输入**：`图片`、`宽度`、`style`、`颜色` 等展示键；**输出**：不进入信息框；空角色或样式角色不加入缺项清单。
3. **状态**：歌曲框参数值内部再出现同名模板；**输入**：参数值里嵌套的歌曲框模板；**输出**：不作为新的歌曲框计数，也不影响首个框的信息框归属。

### 简介与歌词

4. **状态**：页面存在简介章节；**输入**：首个完整简介章节（含同级子标题段落）；**输出**：简介取该章节正文，不因后续标题截断，也不用摘要替代。
5. **状态**：页面存在歌词；**输入**：`poem`、歌词模板或歌词章节；**输出**：歌词保留原文行、空段、括号与和声；`br` 转为换行；Ruby 取表层，表层为空时回退实际唱词。
6. **状态**：页面同时存在多个歌词候选；**输入**：源码顺序上的多个候选；**输出**：取源码顺序的首个候选，不按版本名挑。

### 模板规则配置

7. **状态**：服务启动；**输入**：`server/config/vcpedia_templates.json`；**输出**：按源码 resolved 路径加载一次并冻结；文件、JSON 或描述形状错误时带着字段位置直接失败，不回退内置规则。
8. **状态**：需要调整取文槽或字段别名；**输入**：修改规则文件中的 `text_params`、`field_aliases`、`role_priority` 等；**输出**：无需改 Python 即生效；`role_priority` 顺序属于契约。

### 缺口与补提

9. **状态**：页面确认缺简介或歌词；**输入**：一次抓取结果；**输出**：记录该字段缺口，且不因别处候选非空而被清除；页外未知模板与展示参数本身不构成缺口。
10. **状态**：确有缺项且配置了补提模块；**输入**：`crawler.extraction_llm_module`；**输出**：先把可渲染片段合并进材料，再调用一次补提，只合并请求的缺项，随后用合并结果生成摘要；补提失败仍执行摘要。未配置补提模块时不注册、不调用。
11. **状态**：站点存在动态计数统计；**输入**：含 `count` 后缀模板的源码；**输出**：交给模型的材料不含该计数模板——散文行移除含计数的整句，模板参数行仅移除含计数的分句；不为计数联网。

## 模块与架构

### 模块划分

| 文件 | 职责 |
| --- | --- |
| `wikitext_parser.py` | 按源码顺序遍历结构：信息框、简介与歌词三个独立结果，缺口与计数标记 |
| `template_rules.py` | 规则资源的加载、归一、校验与冻结；只提供查询，不解释表达式 |
| `text_conversion.py` | `nowiki` 与无标志 LC 的字形保护，字段最终一次转换 |
| `source_extraction.py` | 模型材料构造与缺口合并；不调用模型，只替换外部读取 |
| `vcpedia_fetcher.py` | 详情入口；摘要与可选补提的调用时机 |
| `wiki_api.py` | 新增局部渲染的 POST 通道，供嵌入片段取得渲染后的 HTML |
| `daily_new_song_fetcher.py`、`task.py` | 传递可选补提模块；候选口径与落库边界不变（落库仍在 Agent 侧） |

### 接口规范

- `parse_details(source, title, *, with_missing=False)`：返回结果字典；`with_missing=True` 时返回 `(结果, 缺口)`，缺口为 `{"infobox": [...], "summary": bool, "lyrics": bool}`。
- `VCPediaFetcher(config, llm_module=None, *, extraction_llm_module=None)`：新增可选补提模块；`fetch_entity_description` 的签名与返回字段不变。
- `collect_new_song_candidates(config, llm_module=None, *, extraction_llm_module=None)`：新增关键字参数并向下传递，返回口径不变。
- `template_rules`：`descriptor(name)`、`field_key(label)`、`role_priority()` 等查询入口；资源形状错误抛 `ValueError`。
- `source_extraction.material_text(source)`：唯一材料构造入口，一次字形转换后剔除计数再截断。

## 备注

### 关键技术选型

- 结构遍历使用 `mwparserfromhell`；字形转换使用 `zhconv`（结构比较用 `zh-hans`，正文用 `zh-cn`）。
- 嵌入片段需要站点渲染结果，因此 `source_extraction` 使用 `beautifulsoup4` 解析该 HTML 片段；这与抓取路径无关，抓取仍只取 wikitext。
- 渲染片段通过 POST 提交源码，长源码放请求体而不放 URL。

### 非目标

- 不解析远程模板或 Lua 展开，不支持高级 LC（R/A/H）语法。
- 不做语义判卷、版本标签、来源判卷或多版本汇总。
- 不恢复已退役的缓存写回、批次期限、SQL upsert 与关键词补偿设计。
- 不改变世界任务的落库与事实投递边界。

# VCPedia 歌词关键词可用性基线

本文记录一次真实页面采样得到的量化事实，用于给"关键词可用性"设定验收基线。所有数字来自
2026-09-26 对 VCPedia 当日模板页前 12 首歌曲的实测，采样与统计脚本为一次性只读脚本，不修改产品代码。

## 下游实际需求

歌词只经一条链路到达消费者：

```text
wikitext_parser: lyrics + spaced_lyrics=spaced_from(lyrics)
  -> _extract_song_fields -> spaced_lyrics
  -> _split_spaced_lyrics: 按空白切分，只保留 6 <= 长度 <= 50 的片段
  -> NewSongCandidate.lyric_keywords
  -> song_acceptance: 写成 "{keyword}=>{keyword}是《{song_name}》的歌词"
  -> song_entity_linker: flashtext 在用户输入里做子串匹配，认出歌名
```

因此关键词的唯一用途是**在用户话里被匹配到**。它决定两件事：这首歌能不能被认出来（召回），以及
不相干的闲聊会不会认错歌（误命中）。格式保真（换行、括号、和声、原译分离）不进入这条链路。

## 实测事实

### 字段覆盖率

对当日列表前 20 首采样（同一实现、关闭模型）：

| 指标 | 实测 |
| --- | --- |
| 抓取成功 | 19 / 20 |
| `lyrics` 为空 | 0 |
| `summary` 为空 | 0 |
| `infobox` 为空 | 0 |
| 抓取失败 | 1（`谁是世界上最好的矿石？`，标题本身不是歌曲页） |

即字段非空率已接近满值，"提高覆盖率"在本采样下没有可改进空间。空字段与缺口机制主要服务于
上述这类非歌曲页面与将来新出现的页面形态，而不是当前主要瓶颈。

### 片段长度分布

| 指标 | 数值 |
| --- | --- |
| 采样歌曲 | 12 首（均有歌词） |
| 候选片段总数 | 818 |
| 长度：最小 / 中位 / 最大 | 1 / 6 / 27 |
| 因 `< 6` 被丢弃 | 378（**46.2%**） |
| 因 `> 50` 被丢弃 | 0（**0.0%**） |
| 实际进入索引 | 440（53.8%） |

被 `< 6` 丢弃的片段包含大量完整歌词句：`永远的诺言`、`不再有迟疑`、`裂隙在蔓延`、`千秋同所向`、
`开元旧年`、`舞衣振起`。`> 50` 的上界在真实数据里从未触发，且 `spaced_from` 已按标点切句，
片段本身偏短，上界形同虚设。

### 丢弃的主因是切分单位，不是长度阈值

`spaced_from` 用 `[\n，。！？；、,.!?;]+` 切分，把逗号、句号也当作断句点，于是一句歌词被切成多个
短语，短的那部分随后被 6 字下界丢掉。对照实验（同一批页面）：

| 切分方式 | 进入索引的片段数 |
| --- | --- |
| 现状（按标点切 + 下界 6） | 440 |
| 只按空白切（下界仍为 6） | 440 |
| 只按空白切 + 下界 3 | 757 |

### 误命中评估

用 27 句真实语气的闲聊输入（15 句纯中文 + 12 句含拉丁字母）对候选片段做子串匹配：

| 方案 | 纯中文输入误命中 | 含拉丁输入误命中 |
| --- | --- | --- |
| 整行切 + 下界 3（不加过滤） | 0 | **7** |
| 整行切 + 下界 3 + 排除纯 ASCII 片段 | 0 | 0 |
| 整行切 + 下界 3 + 排除「纯拉丁且长度 < 4」 | 0 | **1** |

含拉丁输入的误命中来自《魔法时刻》的 `you`、`hello`，在 `I love you`、`thank you`、`hello 你在吗`
中被匹配。单字母与双字母候选共 36 个，其中纯拉丁 10 个：`A`、`Da`、`Fa`、`Fu`、`NO`、`OH`、`Ra`、
`go`、`is`、`my`。

## 据此确定的验收基线

1. **片段单位改为原文行**：不再把逗号、句号当断句点，恢复完整歌词句进入索引。
2. **长度下界由 6 降为 3**：纯中文输入的误命中为 0，同时把进入索引的片段数从 440 提升到 757。
3. **删除长度上界 50**：真实数据从未触发，且子串匹配下超出用户一句话长度的片段本就没有匹配机会。
   保留一个从不生效的常量只会误导后续维护。
4. **排除"纯拉丁且长度 < 4"的片段**：含拉丁输入的误命中从 7 降到 1，同时保留 `hello`、`love`、
   `BOOM`、`Do-Re-Mi` 与整行英文歌词，英文歌仍可被检索。

### 度量指标

| 指标 | 定义 | 当前 | 目标 |
| --- | --- | --- | --- |
| 字段非空率 | 采样歌曲中 `lyrics` 非空的比例 | 12/12 | 不下降 |
| 片段可用率 | 进入索引的片段数 / 候选片段数 | 53.8% | 显著提升 |
| 误命中样例 | 既定闲聊语料里被匹配到的片段数 | 含拉丁 7 | 不高于 1 |
| 污染片段 | 含 `=>` 或换行的关键词 | 0（由 `spaced_from` 分隔符保证） | 保持 0 |

## 采样与复现边界

- 只读真实站点，不写入生产数据；采样为当日列表前 12 首，**样本量有限**，结论以方向与量级为准。
- 闲聊语料为人工构造的 27 句，用于比较不同方案的相对风险，不是真实用户语料分布。
- 结论适用于"关键词检索可用性"，不覆盖歌词作为角色阅读原文的使用场景；若将来需要朗读歌词原文，
  格式保真需要重新评估。

## 未决问题

- 原文行若含全角空格（如 `虽　然说　还没想好叫什么`），按空白切分是否仍会切断词，需要在改动时用
  真实样例确认。
- 同一片段来自多首歌时索引的行为（`flashtext` 多命中）本文未测。
